# Translation (all 3 layers)

Languages: en, hi (Hindi), bn (Bengali), ne (Nepali), my (Burmese), km (Khmer). Choice is saved as `Preferences.lang` and in `ca_lang` on the device.

## What is translated
- **Interface text** on every screen in all 3 layers: labels, buttons, messages, aria-labels, placeholders.
- Reviewed strings live in one list (`CA_TR` in `ui_kits/confirm.js`). In the prototype, strings not yet on that list are drafted by the model and cached per language. **Every draft needs native-speaker review before launch.** For production, export all strings to a translation system (e.g. i18next JSON per language) and ship only reviewed files. No live machine translation in production.

## What is never machine-translated (`data-no-tr`)
- Dictionary definitions, Faith mode blocks, sources, verse text.
- Anything a person typed: check-in notes, monthly answers, crisis notes.
- Tradition terms (karma, saṃsāra, mūrti…) stay as written.

If a definition has no reviewed translation, the page shows it in English with: "Not in this language yet."

## Backend
- `GET /terms/:term?lang=` returns `{ def, lang }`; `lang` is "en" when no reviewed translation exists.
- Monthly answers and check-ins are accepted in any language; concept grouping must match across languages (e.g. "শান্তি" = "peace") before counts reach the map.
- Verses come only from licensed Bibles per language; otherwise "The dictionary does not cover this yet."
